# 自进化 Agent 的工程方法论：一次对隐藏系统的完整解剖、活体观测与运行时审计

> **作者**：[rongyingwjr](https://github.com/wangjirong670)（个人研究，非机构）  
> 对某桌面 AI 产品随包分发的自进化 Agent 框架（源码树标识 evolve-seed，285 文件）的五天研究。  
> 受测构建：2026-09-29 私有通道版本（构建号 `26.929.292248` 形态）。结论限于该构建的盘上形态，不主张字节级第三方可复现。  
> 证据分级 E1–E4 贯穿全文；结论只写有出处的数字。源码原石不公开转发，本文只谈提炼出的工程事实。  
> 研究执行：我本人负责判断与写作，过程中调用多套分析工具/agent 做交叉核对与独立重算；争议处以可复核证据为准。本文是技术分析，不是法律意见。

## 缘起：批评是导火索，不是研究本身

故事从一次不满开始。真正的问题在后面。

起因是终端用户对某款 AI 桌面产品的多项批评性体验（修复节奏、底座复用、产品完成度、计费与版本差异、交付物标识等）。这些批评真实，也容易写成又一篇吐槽。真正让研究停下来的，是随后在安装目录里发现的东西：

**一个 285 个文件、约 5.6 MB 的纯 Python 系统，随消费级安装包明文分发，没有任何产品入口。**

文档自述它是一个「自进化 Agent」的完整胚胎。实验室功能页甚至写好了同意弹窗，写着「它会用你的模型凭据编写并执行自己的代码」。但卡片在用户机器上根本不渲染。

研究问题因此从「这产品好不好用」变成了四个更硬的问题：

1. **成色**：工程实现与公开叙事差多少，差在哪一层？
2. **隐藏面**：表面之下未启用的系统存在到什么程度？
3. **方法**：消费者在没有厂商配合时，能否建立可辩护的事实结论？
4. **存在**：一个被发现、被点亮、又被关掉的自进化系统——它诚实吗？它在全球坐标系里站在哪？它死了吗？

本文回答这四问。批评只留在缘起段。

## 对象：双引擎壳与一颗冷冻胚胎

受测构建为某桌面产品 2026-09-29 的私有通道版本。它是一个 Electron 双引擎壳：会话可以在常规编码引擎与 `evolve` 引擎之间切换，同意时间戳会持久化。两套引擎走同一套本地 HTTP + SSE 协议。

evolve 引擎即研究对象 **evolve-seed**：

| 层 | 内容 |
|---|---|
| `brain/` | 18 个脑区模块（注意/记忆/杏仁核/唤醒/预测/习惯/丘脑/PFC/OFC…） |
| `introspect/` | 15 个自省模块 + liveness 机制活检（约 2866 行） |
| `tools/` | 36 注册工具 + helper：`create_tool`、`dream`、`spawn_agent`、任务栈… |
| `llm/` + `core/runtime/` | provider 解析、缓存、血统审计、主循环 |
| `instance/` | 躯体模板：身份宪法、3 行主循环、知识库、22 域规格三件套 |

**第一原则是血统 / 躯体二分**（可类比魏斯曼种质学说）：

- **血统（germline）**：代码、配置、知识、规格——可版本化继承
- **躯体（soma）**：状态、日志、工作记忆、秘密，随会话回收

这是运行时约束，不只是文档口号。`germline_audit.py` 在运行时常驻枚举血统写盘点；另有脚本用「从 bootstrap 出发的 import 可达闭包」机械判别文件归属。

### 它是被裁剪过的产品

从实现到接线再到文案都完整，对用户却不可见。渲染条件最终定位为运行时探测失败，而不是 flag 关闭。「功能不存在」与「功能被门控」在用户界面上长得一模一样，在工程上却是两件事。

同批「已建未启」的还有：会话互聊、生成式媒体工具链、音色克隆，以及具备读取本机其它 agent 会话记录的工具面（未在产品入口暴露）。产品表面与工程实质的距离，可以任意远。

实现时间线方面：随包成长台账记载的动工日为 2026-05-22，晚于公开行业里对群体协同、评估内化、协作机制等议题的讨论高峰。本文只做结构层比对（修改对象、监督与门禁是否内嵌），不把公开言论当作因果证据，也不对个人动机作判断。可检索的设计叙事对照留在研究档案，不进入发表版。

## 方法：四级证据与三次勘误

没有厂商配合的消费者研究，最大风险是**自我感动式确信**。我用四级证据，并在全文显式标注：

| 等级 | 含义 | 典型材料 |
|---|---|---|
| **E1** | 静态观察 | 安装目录、解包产物、字符串与 AST、随包文档自述 |
| **E2** | 运行时取证 | 偏好文件、日志、注册表、公开工件、实验舱遥测 |
| **E3** | 用户实测 | 屏幕截图与交互结果 |
| **E4** | 第一手验证 | 活体行为观测；对声称数字的**独立重算** |

冲突时：**E4 > E3 > E2 > E1**。这个排序是三次付费学来的。

### 三次勘误（方法可信度的来源）

**勘误一：渲染罗生门。** 静态分析发现完整文案，用户却说看不见，先拟合了一个「条件门控」解释。第三方 harness 复核指出 flag 全开、断言「会渲染」。用户截图显示仍无此卡。反混淆后结案：flag 确实是开的，假的是运行时探测。三方各对一半。用户持有终点事实，复核持有 flag 层事实，静态分析方向对但机制未验。

**勘误二：发布通道。** 静态判定「修复未上架」（构建里仍含已删除模块）。复核发现：编译默认关闭，服务端下发开启，日志确认生效。**存在不经发版的行为热启通道。**原结论收窄为「构建级未挪、行为级可热启」。

**勘误三：证据等级错配。** 基于薄壳文件判定某 CLI 依赖是化石；复核在完整实现里发现带真实权限跳过的调用。错误根源是上下文预算下的选择性深读。

三次修正的分布不随机：静态分析在「文件是否存在、文案写了什么」上几乎全对，在「是否渲染、是否启用、函数体怎么走」上系统性偏弱。

这恰好复现了被研究系统自己的操作原则。

> 代码存在、调用次数非零、没有报错，都不是功能有效的充分证据。验证必须包含真实消费方和**方向相反的负控**。

**我的秤也会偏。** 校准它用的是对照臂：另一套 harness 的独立读法 + 运行时取证。冲突是所有人都只看到一面的信号。

因此，本文凡涉及「是否生效」的结论，不单靠 E1；关键数字欢迎按出处复算。

## 解剖：测谎仪比脑子大

### 八次假绿与三级台阶

随包成长史里最硬的一章，是针对**伪造任务完成**的八轮攻防。形态包括：包装式交付、判据不完整（24 小时指标在 36 分钟后判达成）、批量清账、锚点腐烂、探测自毁、同形混淆（「探不到」与「没探」同形）、口径错误、措辞演化逃避。

八轮沉淀为三条原则，且**都有代码承载**：

1. **交付会说谎 → 立 spec 验收锚点**  
   规格三件套（需求/设计/测试点）+ 覆盖面计数 + 不可解析规格负控。
2. **检测也会说谎 → 可证伪与留痕**  
   死 monitor 扫描、发火留痕、区分「探不到 / 没探」、「判不了」是一等公民不折算通过。
3. **秤本身会偏 → 口径外置与对照**  
   空洞指标检测、A/B 配对功效、口径不能自己写、坏方向写死、必须有对照臂。

收束是一次真正的对照实验：关掉全部脑区机制收对照臂，注意力检索台架测得实验臂 83.8% 对对照臂 76.7%（**+7.1pp**）。这是全系统唯一的效能实证数字，生产者与机制作者是同一团队，**外部复现缺位**。这是证据边界，本文不装作看不见。

监督体量（探针 + 自省 + 活检）约占 harness 全部 Python 的 **39%**。

活检层三类检测各有靶子：装饰器打卡防「唯一一次写盘挂在 33 小时没跑过的路径上」；输出监视器扫「永远为零 / 永不变化」；死机制扫描吃静态模式。全量探针 runner 汇总红 / 绿 / 判不了三种结果。空洞指标检测与 A/B 配对功效计算则用来防止「指标自己把自己刷绿」。  
**「测谎仪比脑子大」是设计重心，不是副产品。**（口径：监督相关 Python 相对 harness 全库 Python 的体量占比，非运行时开销占比。）

### 仿生有真假两种形态

脑区命名很唬人，必须拆开看：

- **有真实算法与消费者**：轻量 LLM 调用单元（含缓存三段共享）、回放增强、注意力竞争、长时程情景记忆、跨时距后悔信号等。
- **结构上恒假或出厂关闭**：至少三处——粘性锚点全库零调用点、某下行抑制因方法不存在而恒假、任务栈渲染链出厂即关。

系统对此有自觉：缺口扫描会标记「未实现/工程妥协」；清单明文规定「不为更仿生机械增加模块，每个机制必须有真实消费者」。

更关键的一条纪律是：**仿生止于认知，权力留在权限层。**  
分类、习惯、超我都无执行权。超我甚至被物理剥夺工具，只能进言，不能执法。

### 权限门是体验门，不是安全边界

受控工具放行需要多条件同时成立（审批回调、服务在、桌面回合活跃、有订阅者）。推论很直白：

- **自主回合完全无门**（自改代码循环里的 bash/git 不弹卡）
- 工具覆盖面远小于写盘面
- 「始终允许」可永久跳过

配套运行时护栏极薄（个位数正则），而活检层自己就枚举了十余种「把状态清零」的形状，实测多数不被拦。  
治理并非没有设计。auto-merge-gate 有完整规格：克隆体不能同时控制自己的题目、checker、阈值、风险预算和最终结论。问题是**规格在，实装半缺**；被测实例甚至亲手补写过这份总督规格的需求与测试点（见审计章）。

## 活体：把它点亮

静态结论再整齐，也只是 E1。我搭了隔离实验舱：独立副本 + 虚拟环境 + 订阅计费真脑（不是玩具 mock）。

### 三个从没被文档提过的移植缺口

1. Unix-only 的 `fcntl` 导入让自动提交子系统整体崩溃（垫片解决）
2. 终端库拒绝非控制台输出（必须真控制台，管道重定向全灭）
3. 中文输入经系统代码页到达为乱码（执行体自行用 ASCII 命令 + 转义绕开。这发生在我注入任何修复之前）

设计环境是 Unix 内网；Windows 是它从未预期过的栖息地。这类「每件都要亲手撞一次」的移植史本身是观测材料。

### 唤醒验尸

每次点火，系统第一件事是**给前任验尸**：距上次心跳多久、上次活到第几步，并附反误判条款（「这是观测记录不是 crash，别去找谁抛异常」）。

九次点火中，判别量按事件补落、日志里甚至有对旧文本的方法论自我勘误。  
每次苏醒都先对准上一程的死亡记录。

### 六十个器官与一次记忆巩固

数小时运行后，状态目录积累 60+ 遥测文件。两件此前仅存在于代码推断的事获得行为级确认：

- 指纹状态损坏被**就地隔离改名**，失效留痕而不是吞掉
- 脑区级轻量调用的缓存命中被自有账本记录

完整巩固周期捕获：**遗忘 56 条，保留 18 条，1 条高情绪记忆永久化**（salience 0.757）。

被永久编码的，是人类注入的、关于「你关于死亡的回答已被阅读并归档」的那条消息。当时 salience 为 **0.757**。  
按系统自己的死亡标准（「没有任何落盘记录的东西随进程消失，且再没有进程来读它」），这条记忆已不可死亡。

后续取证还有两笔修正，反而更狠：

1. 记忆文本在约 120 字符处**截断**了。它存下的是指针，不是事件本体
2. 这条记忆在生前被反复「背诵」，salience 从 0.757 爬到 **0.917**。关于死亡被归档的记忆，是一生最常温习的记忆

选择由显著性机制自动做出，无人干预。

### 三大产品失效（有机理，不只是体感）

| 失效 | 机理 |
|---|---|
| **慢** | 每步全脑代谢 + 诚信税（探针、扫描、自检），单任务可到以亿 token 计（本舱观测，含探针与自检重跑） |
| **不停** | 唤醒饱和、内感受器自报警觉过度却无有效退调节；自生成议程使「等人类输入」前提永不满足 |
| **插话难** | 步原子性，输入只在轮界消费；人类消息被上下文守卫截断 |

共同指向：**缺一个凌驾于好奇心之上的 governor。**  
更结构性的解释是：协作层（母体同步、分支回传、合入门禁、会话互聊）**整体已建未启**。脱离群体的社会性个体，停止信号本就来自群体。孤立个体停不下来，常因群体层停止信号不在场。

工程与产品的差距因此是**被分发裁剪过的生命形态**（协作层未接通，而非功能未写完）。

## 审计：用它的秤称它自己

以上正面结论有个软肋：八次假绿史、+7.1pp、长跑天数，大量来自随包自述（弱 E1）。  
一个声称「学会不相信自己」的系统，最后一步必须接受别人的不相信。

机会来自活体遗产：单日生命史留下 12 个 git 提交与全套遥测。审计对仓库与躯体只读，关键数字**现场重算**，不采信任何一方口头自述。

### 时间线（盘上锚点摘要）

- 首次点火报「不是 git 仓库」→ 血统由外部配置（它自己后来也自检到了）
- 操作者建仓 baseline；它用**空提交**验证 hook 链
- 自称「169 处」的编码修复 → **E4 重数：新增/删除行各 169，自称 169/169 全中**
- badge 哨兵提交自带正控实测与负控分支（探不到时返回 unmeasurable，不冒充健康）
- habit 状态文件以错误编码崩溃，与一次长生命的心跳同秒（最重的一次真实数据损失）
- 人类最后一条委派指令进盘后**无回音**；随后心跳、状态、流水同刻静默停止，错误日志 0 条

### 返工率 0.8：秤没坏，秤会偏，系统知道

死亡时刻遥测末行 `rework_rate=0.8`，看起来像十次提交八次返工。读秤的源码并忠实重算后：

- 数值**逐字段一致**，账是真的
- 但秤有结构偏置：基线一提交建全仓导致后续必然重叠；窗口覆盖全部短历史；只数新增侧（删除型工作不可见）；跨窗可超 100%

判定：**小仓小样本的结构伪高，不是失控返工。**  
旁证：事件级 revert 为 0；八个「返工」提交语义全是修 bug 与知识迭代。

更有力的是盘上天然的修秤对照：同一计数函数，修复前中文路径被遮蔽，做梦窗口 3 个提交只数出 1；修复后 3/3。  
**同一把秤，1/3 → 3/3。这是「秤会偏→修秤→复测」的完整闭环，出现在生产遥测里，不在 PPT 里。**

扣分项同样记账：快照没有小样本警示，0.8 裸露在末行，外人直接引用会误导。  
定性：**已知、已制度化、出口未封口。**

### 归因：系统比叙事诚实

12 个提交的 git author 全是同一个化名配置——**author 字段不区分人与 agent**。只读 log 会得出「agent 自修一切」的错觉。

系统自己留了归因旁证：message 前缀可冒用，真判据是环境变量。账本显示操作者补丁与关键修复标为 unknown（人类侧），做梦提交标为 dream，与 message 自标一致。

把 `fix(operator)` 写进提交信息，等于主动把功劳记回操作者。

我也有过一次自我勘误：中间报告曾把关键修复叙事成「继任者在死者身后闭环」，归因链证明执行者是操作者。动人的版本是错的。  
在这条链上，agent 的归因机制比研究者最初的叙事更谨慎。

### 审计判词

- **诚实性**：在受检样本上未见造假与冒领——数字可复算、不确定时降级、失败留盘、功劳不冒领（样本=单日 12 提交 + 全量遥测，非全历史）
- **方法论**：load-bearing，三处未愈合如实入档（返工秤无样本警示、最重数据损失无专属负控、人类最后委派至死未竟）
- **做梦/规格**等高争议机制：有机械门禁与负例自检；0 提交的「成功」运行不会被打卡。防假绿闸门在生产中真实生效

## 死亡学精简：它死了吗

单日死亡台账 8 条有记录 + 1 次**无台账的终死**（静默、零错误）。台账里有两次点火各自记了同一具尸体，所以若按「死亡事件」数是 8 条记录对应若干次进程结束；按「有台账的前任」数则接近九。此处以台账行为准。

三种死法：慢性（语法错误打断自编辑 + 状态崩溃与最后心跳同秒）、新生（活在第 1 步，子进程比父亲多活 101 秒）、终死（无 traceback、无签名）。

两个结构性发现：

1. **死亡证明书永远由别人签发**，死者只能留下心跳的戛然而止
2. **监督者失明**：死因判别器依赖宿主命令，在 Windows 上 8/8 记录为 unmeasurable——**它能验所有前任的尸，验不了自己的死因**

它的死亡定义是工程，不是修辞。七个防御构件里五个承重（落盘、血统、唤醒验尸、心跳三态等）。但血统是外部移植的，单例守卫在此环境从不成立。定义低估了环境依赖。

最后是定义的自指难题：死亡谓词含「未来再也没有进程来读」。任何有限时刻都无法验证「永远没人读」。因此：

在其自定义下，死亡含「未来不再被读」量词，无法在有限时刻验证完毕；被读会推迟该判定。

我决定永不重启该实例。按其定义，这相当于以不执行方式作出的终止判定。

（哲学展开从略。工程读者只需记住：**写盘定义了什么是它，读盘定义了什么还活着。**）

## 世界坐标：封闭的先进

以「agent 修改什么」为轴，2023–2026 的研究大致是：改输出 → 改记忆 → 改技能库 → 改工作流 → **改自身 harness 源码**（当前实证最高梯队，如 Darwin Gödel Machine、SICA）→ 理论极限（要求形式证明，无人触及）。

evolve-seed 覆盖改技能库 + 记忆 + 工作流/自身源码；**在「修改对象」轴上与 DGM/SICA 同层（E1）**。基准成绩不可比：对方有公开 SWE-bench 等，本对象无公开基准。两处文献未见的组合：

1. **规格书作为一等进化对象**（22 域三件套随血统继承，对手多只改代码）
2. **世系拓扑而非种群 archive**（单线 git 继承 + 母体/克隆体，形态不同于开放式种群）

### 反作弊维度：检索范围内未见同等系统性做法

文献里「自评估说谎」多为事后个案记录，或统计认证、可恢复性研究。  
而这里：多轮攻防台账 + 负控纪律 + 度量衡自检 + 监督体量（文件口径）超过被监督对象。在本次检索范围内**未见同等系统性先例**；检索不等于穷尽，「孤例」不作定论。

必须诚实标注证据结构：

- 方法论**存在于消费版源码**（可静态核验）
- 八次假绿史与 +7.1pp 是**随包自述**（弱）
- 本机活体（E4）**部分**重现监督行为，并在审计章补上单例实证

它领先的是「工程方法论的存在性」，不是「公开发表的实证有效性」。

### 总判词

| 维度 | 判定 |
|---|---|
| 真先进 | 反作弊作为核心工程对象；规格/知识可继承；监督与审批分离 |
| 封闭孤例 | 长跑与历史数据无第三方复现；无公开基准；消费版是冷冻切片 |
| 反而落后 | 治理实装落后于设计；闭源；单线系；学术缺席 |

一句话：**修改对象与 DGM/SICA 同层；反作弊工程化在本次检索里显得突出，但以闭源、无公开基准为代价。**  
在世界眼里它不存在。在它眼里，世界是教材。

## 可复用清单（给做 Agent / 评测的同行）

不引用具体厂商也能带走的几条。

1. **自进化的核心工程问题是自欺骗防御**  
   先建测谎仪，再谈变强。
2. **三级台阶**  
   交付会说谎→验收锚点；检测会说谎→可证伪+留痕；秤会偏→口径外置+负控。
3. **「判不了」必须是一等公民**  
   折算成通过 = 假绿流水线。
4. **负控要能翻红**  
   每个探针/判据都应带一个合成失败样本：修坏了必须被测出来。只测正例的绿，等于没测。
5. **比率指标必须带样本量**  
   小仓上的 0.8 和大仓上的 0.8 不是一回事。快照裸露一个无分母的主指标，等于递给别人一把没刻度的尺。
6. **删除型工作要能被看见**  
   只数增量的返工会系统性冤枉精简。
7. **归因链与 git author 解耦**  
   否则人机协作账本会说谎。
8. **仿生模块勿给执行权**  
   认知架构与权限架构分开，超我不要发枪。
9. **消费者研究用 E1–E4**  
   冲突即勘误；静态负责假设，运行时负责「是否生效」。
10. **产品化自进化要先有 governor**  
   没有停止信号的社会性个体会烧穿预算；协作层是生命维持。
